# Автоматизация Python-окружения через Make

Этот проект реализует воспроизводимую среду разработки. Вместо ручного управления зависимостями используется **Makefile**, который служит единой точкой входа.

## Логика работы

1.  **Stateless Environment**: Мы отказались от `source venv/bin/activate`, так как Make запускает команды в разных shell. Вместо этого инструменты вызываются напрямую: `$(VENV)/bin/python`. Это гарантирует использование проектного окружения, а не системного.
2.  **Управление зависимостями**: Таргет `install` привязан к состоянию файла `requirements.txt`. Окружение обновляется только при изменении списка пакетов.
3.  **Цепочки проверок**: Таргет `make check` объединяет статический анализ и проверку зависимостей в единый граф, гарантируя качество кода перед запуском.

## Инструкция по использованию

Все действия автоматизированы. Основные команды:

| Команда | Описание | Инструмент |
| :--- | :--- | :--- |
| `make install` | Создание `.venv` и установка пакетов | `pip` |
| `make run` | Запуск приложения через изолированное окружение | `python3` |
| `make typecheck` | Проверка аннотаций типов | `mypy` |
| `make lint` | Проверка стиля кода (без изменений) | `flake8` |
| `make format` | Автоматическое исправление форматирования | `black` |
| `make check-requirements` | Поиск пропущенных библиотек в конфиге | `pip-check-reqs` |
| `make check` | Запуск всех проверок (lint + typecheck + deps) | - |

## Ожидаемые результаты

* **Надежность**: Код `src/app.py` упадет с ошибкой при обычном запуске, если нет библиотек, но успешно отработает через `make run`.
* **Контроль**: `make typecheck` обнаружит несоответствие типов в `src/calc.py` (например, передачу строки в функцию сложения целых чисел).
* **Чистота**: После выполнения всех команд Git не зафиксирует новых файлов благодаря настроенному `.gitignore`.
